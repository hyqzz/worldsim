# WorldSim —— 物理世界模拟基础设施平台 · 总体技术方案

> 版本 v0.1 (草案) | 状态: 待评审
>
> 定位: 一个以真实物理定律为内核、以算力预算驱动精度、以通用接口对外服务的数字物理世界平台。
> 一句话: **把"物理世界"做成一种可以按需分配算力来租用的基础设施。**

---

## 0. 需求理解与边界声明

### 0.1 平台必须做到

| 编号 | 需求 | 本方案对策 |
|---|---|---|
| R1 | 提供物理世界模拟的基础设施 | 多世界实例管理 + 服务化架构 + SDK |
| R2 | 任何项目可通过通用接口接入 | 控制面(REST) + 数据面(gRPC/WS) + 三语言SDK |
| R3 | 根据算力调节任意精度 | 五轴精度模型 + 预算控制器 + 注意力驱动的区域LOD (§5) |
| R4 | 纯数据接口模拟(headless) | 模拟核心零渲染依赖，渲染只是可选订阅者 |
| R5 | 图形化形象展示 | 独立渲染进程 + 流式状态同步协议 (§8) |

### 0.2 物理边界（诚实声明，写入产品文档）

- 模拟的是**遵循真实物理定律的自洽世界**，不是我们宇宙的逐原子复刻（混沌 + 算力墙，原理上不可能）。
- 量子效应以有效模型进入（材料参数、化学反应速率），不实时求解量子多体波函数。
- 尺度覆盖目标: 分子级(~10⁻⁹ m) 到 宏观工程级(~10³ m)；单世界时间跨度无上限（可快照续跑）。

## 1. 总体架构

```
┌────────────────────────────────────────────────────────────────────┐
│  客户端层    Python SDK · TS SDK · C++ SDK · CLI · 浏览器Viewer      │
├────────────────────────────────────────────────────────────────────┤
│  接入层      API Gateway: REST(控制面) / gRPC+WS(数据面) / 鉴权/限流  │
├────────────────────────────────────────────────────────────────────┤
│  世界管理层  世界生命周期 · 快照/恢复/分叉 · 调度器 · 资源配额         │
├────────────────────────────────────────────────────────────────────┤
│  模拟核心 (Simulation Kernel)                                       │
│  ┌──────────────────────────────────────────────────────────────┐ │
│  │ 主循环: 时钟 → 事件队列 → 区域LOD决策 → 各求解器步进 → 耦合交换  │ │
│  ├──────────────────────────────────────────────────────────────┤ │
│  │ 物理求解器栈 (按LOD分层, §4):                                  │ │
│  │   L4 ab-initio/量子化学(插件, 极小体积)                        │ │
│  │   L3 全原子分子动力学 (力场+恒温恒压)                          │ │
│  │   L2 介观: 粗粒化MD / DPD / LBM                                │ │
│  │   L1 连续介质: FEM(固体) FVM/FLIP(流体) MPM(弹塑体) 网格场      │ │
│  │   L0 刚体动力学 + 碰撞 + 约束                                  │ │
│  ├──────────────────────────────────────────────────────────────┤ │
│  │ 场系统: 引力场/电磁场/温度场 (全局网格, FFT/multigrid求解)       │ │
│  │ 耦合层: 细化(refine)/粗化(coarsen)算符, 握手区守恒通量交换 (§4.4)│ │
│  └──────────────────────────────────────────────────────────────┘ │
├────────────────────────────────────────────────────────────────────┤
│  精度管理层  五轴精度模型 · 算力预算分配器 · 自适应质量控制器 (§5)     │
├────────────────────────────────────────────────────────────────────┤
│  存储层    状态快照(chunked) · 输入日志(确定性重放) · 轨迹导出(Parquet)│
├────────────────────────────────────────────────────────────────────┤
│  计算后端   CPU线程池 · GPU(wgpu compute) · [后期]分布式worker        │
└────────────────────────────────────────────────────────────────────┘
        │ 状态流(只读)                    ▲ 注入指令(受控)
        ▼                                 │
┌────────────────────────────────────────────────────────────────────┐
│  呈现层(独立进程) 渲染器: 实例化网格/PBR · 等值面/体渲染 · 矢量场可视化 │
│  数据通路: 内核环形缓冲 → FlatBuffer帧 → WS/QUIC → 客户端插值平滑     │
└────────────────────────────────────────────────────────────────────┘
```

**三条架构铁律**
1. 模拟核心不依赖任何渲染/接口代码；渲染与API是状态的只读观察者。
2. 一切干预（施力、注热、生成实体）都是带tick号的事件，走统一因果序。
3. 所有宏观参数最终可追溯到常数层推导（材料库由下层模拟标定，§4.5）。

## 2. 核心领域模型

| 概念 | 定义 | 关键属性 |
|---|---|---|
| **Constants** | CODATA-2022 常数集(c, ħ, G, e, k_B, ε₀, N_A…) | 只读，全平台唯一来源 |
| **World** | 一个隔离的模拟宇宙实例 | id, 时间轴(tick), 种子, 配置, 状态版本链 |
| **Region** | 空间的八叉树/Morton网格分区，精度的调度单元 | lod等级, dt, 所辖实体/粒子, 脏标记 |
| **Entity** | 物质的组织形态 | 类型(刚体/连续体/粒子团/分子), 材质引用, 状态 |
| **Material** | 材料参数库 | 密度/杨氏模量/粘度/导热率… + 来源标注(常数推导 or 下层标定) |
| **Field** | 全局物理场 | 名称(gravity/em/temp), 网格分辨率, 数值格式 |
| **Sensor** | 虚拟测量探针（测量是一等公民） | 位置/体积/采样率/物理量, 读数=局部场时空平均 |
| **Actuator** | 受控干预器 | 力/热源/边界条件, 生效区间 |
| **Event** | 因果事件 | tick号, 类型(碰撞/越阈/注入), payload |

空间寻址: `world_id / region(morton64) / entity(uuid)`；一切查询和注入都以此三元组定位。

## 3. 单位制与数值基础

- 内部严格 **SI 单位制**，float64 运算；API 层提供单位换算助手。
- 常数层示例（`ws-core`）：

```rust
pub mod constants { // CODATA-2022
    pub const C:  f64 = 299_792_458.0;          // 光速 m/s (精确定义)
    pub const H_BAR: f64 = 1.054_571_817e-34;   // 约化普朗克 J·s
    pub const G:  f64 = 6.674_30e-11;           // 引力常数
    pub const K_B: f64 = 1.380_649e-23;         // 玻尔兹曼 J/K
    pub const E_CHARGE: f64 = 1.602_176_634e-19;
    // ε₀ 由 α 与 ħ,c,e 导出; 不允许出现魔法数
}
```

- 确定性策略：同二进制 + 同硬件位级确定；跨平台提供"统计一致"级别并文档化浮点差异。所有随机性来自 `(world_seed, tick, stream_id)` 派生的PRNG流 → 可回放、可分叉。

## 4. 物理求解器栈（分层细节）

### 4.1 分层总表

| LOD | 理论 | 典型尺度 | 数值方法 | 稳定性约束 | 相对成本 |
|---|---|---|---|---|---|
| L0 | 刚体动力学 | ≥mm | 半隐式欧拉+辛修正; 碰撞BVH broadphase + 投影Gauss-Seidel接触求解 | dt~ms级即可稳定 | 1× |
| L1a | 固体连续介质 | mm–m | FEM(线弹性/超弹性), 显式中心差分或隐式Newmark | CFL: dt≤h√(ρ/E) | 10× |
| L1b | 流体 | mm–m | FLIP/APIC(液体) 或 网格FVM(气体); 温度对流扩散 | CFL: dt≤C·h/(u+c_s) | 10× |
| L1c | 弹塑/颗粒 | mm–m | MPM(雪/泥沙/粉碎) | 同CFL族 | 20× |
| L2 | 介观 | µm–mm | 粗粒化MD / DPD / LBM | 软势dt~ns | 10³× |
| L3 | 全原子MD | nm–µm | 速度Verlet + SHAKE约束; Bussi恒温, Parrinello-Rahman恒压; PME长程静电 | dt=1–4fs | 10⁶× |
| L4 | 量化/量子化学 | Å–nm | DFT等，离线插件，产出L3力场参数 | — | 离线 |

> L4 不在线运行：它的角色是"最底层常数消费者"，为 L3 生成势函数，保证参数链条最终扎根于基本常数。

### 4.2 场系统
- 引力：区域内部直接牛顿引力对(Barnes-Hut θ=0.6) 或 FMM；行星级用球谐展开。
- 电磁：准静态近似为主（静电 multigrid、静磁 Biot-Savart 聚合）；全 Maxwell 仅在声明需要的区域开启（Yee网格FDTD，CFL: c·dt≤h/√3）。
- 温度场：对流扩散方程，与流体求解器共享网格。

### 4.3 时间系统：多速率子步进
```
宏观tick(如60Hz, dt₀=1/60s)
 └─ L1区域子步 n₁×dt₁ (dt₁≈0.2ms, 满足CFL)
     └─ L2区域子步 n₂×dt₂ (dt₂≈ns)
         └─ L3区域子步 n₃×dt₃ (dt₃≈2fs)
耦合交换发生在每层父步边界: 通量(质量/动量/能量)守恒校验, 误差>阈值则回退该区dt
```
- 休眠机制：速度低于阈值的刚体/区域进入睡眠，事件唤醒（省算力的第一大户）。
- 时间控制原语：`pause / resume / step(n) / set_rate(x)`；支持超实时(批量推演)与亚实时(高精交互)两种调度策略。

### 4.4 跨尺度耦合（本方案的技术心脏）
- **细化 refine**（低→高）：连续场插值出粒子初始条件（FLIP粒子从网格双线性取样）。
- **粗化 coarsen**（高→低）：粒子统计矩（密度/速度/温度的体积平均+通量）回馈网格。
- **握手区**：高低LOD重叠2~3个单元，双向通量交换；每tick核对质量/动量/能量三项守恒残差，超阈值自动降低该区细化等级并告警。
- 这套 refine/coarsen 算符是平台的核心资产，MVP 就要定型其接口。

### 4.5 材料自标定管线（"涌现"的落地方式）
```
常数层 → L4-DFT(离线) → 分子间势 → L3-MD小盒模拟(平台内运行!)
        → 测量输运系数: 粘度η(Green-Kubo), 扩散D(Einstein关系), 热导λ
        → 写入材料库, 供 L1 连续介质求解器使用
```
验证锚点示例：MD 盒中布朗粒子测得 D，检验是否满足 **D = k_BT/(6πηR)**——一条横跨 L3↔L1 的物理定律自洽性测试，也是平台正确性的招牌演示。

## 5. 精度管理体系（对应 R3 的完整设计）

### 5.1 五个正交精度轴
| 轴 | 含义 | 可调范围示例 |
|---|---|---|
| A1 空间 | 网格间距h / 粒子数密度 | 1cm ↔ 1nm |
| A2 时间 | 步长dt（受稳定性下限约束） | 16ms ↔ 1fs |
| A3 模型 | LOD等级 | L0 ↔ L3 |
| A4 方法阶数 | 格式精度 | 1阶迎风 ↔ 4阶中心 |
| A5 容差 | 迭代求解器收敛ε | 1e-3 ↔ 1e-12 |

### 5.2 注意力驱动的区域分配（核心机制）
```
注意力图 AttentionMap = Σ 用户相机视锥 + API声明的兴趣区 + 传感器视野 + 最近交互点
每个region得分 S(r) = 注意力强度 × 物理活动度(动能/温度梯度等)
预算分配器: 给定算力预算B(wall-clock ms/tick), 按 S(r) 降序贪心提升各轴,
            直到预算耗尽 → 输出每个区域的五元组(A1..A5)
质量控制器: 实测每tick耗时, PID反馈微调; 带迟滞防止精度振荡
```
- 两种模式：**交互模式**(锁帧率，如60Hz) 与 **批处理模式**(锁精度，跑多快是多快)。同一内核，不同调度策略。
- 用户可三档介入：全自动 / 区域手动锁定 / 全局预算调整。API 见 §6。

### 5.3 精度切换的正确性保障
- 升级(L0→L1)：需要该区域的历史场数据 → 强制先粗化重建缓存再细化，切换瞬间做一次能量/动量对账。
- 降级：粒子态粗化为连续场，多余细节丢弃但记录在案（分叉调试用）。
- 切换是事务性的：失败即回滚到旧五元组，绝不允许半细半粗的中间态泄漏。

## 6. 对外接口设计（对应 R2/R4）

### 6.1 控制面 REST（低频管理操作）
```
POST   /v1/worlds                     创建世界{seed, constants_override?, bounds, init_scene}
POST   /v1/worlds/{id}/control        {action: pause|resume|step|set_rate, arg}
POST   /v1/worlds/{id}/snapshots      打快照 → {snapshot_id}
POST   /v1/worlds/{id}/fork           {from_snapshot} → 新world_id
PUT    /v1/worlds/{id}/precision      {policy:"auto", budget_ms:8} | {regions:[{mort, lock:{lod:3,dt:"2fs"}}]}
GET    /v1/worlds/{id}/stats          每区域LOD/耗时/守恒残差
```

### 6.2 数据面 gRPC/WS（高频状态交互）
```protobuf
service WorldStream {
  rpc SubscribeState(StateQuery) returns (stream StateFrame);   // 区域订阅, 增量帧
  rpc Probe(PointQuery) returns (ProbeReading);                  // 点探针: 场值/体素均值
  rpc InjectEvents(stream SimEvent) returns (Ack);               // 施力/生体/设边界
  rpc StreamSensors(SensorSpec) returns (stream SensorReading);  // 传感器订阅
}
message StateFrame {
  uint64 tick; double t;                 // 双时钟: 整数tick防漂移 + 物理时间
  repeated RegionDelta regions;          // 变化区域增量, FlatBuffers二进制
}
```

### 6.3 语义约定
- 注入事件在下个 tick 边界原子生效；同世界内全序因果。
- 查询默认返回 `t_head`（最新已提交态），可指定历史 tick（走快照/重放）。
- 所有物理量显式带单位字段（SI 默认），SDK 层做换算。

### 6.4 SDK 优先级
Python（科研/数字孪生主力，NumPy 零拷贝视图）→ TypeScript（浏览器Viewer/游戏）→ C++（嵌入式/高性能客户）。

## 7. 状态持久化、回放与分叉

- **快照**：按 Region 分 chunk 的不可变块 + manifest(内容寻址哈希)，天然支持增量快照与去重存储。
- **确定性重放**：`state₀ + seed + 输入日志(全部事件流) ⇒ 任意时刻状态`。重放日志是权威记录，快照只是加速检查点（每N tick一个，seek时最近快照+短重放）。
- **分叉**：COW 引用共享 chunk，从任意快照派生平行宇宙，用于对比实验/A/B测试。
- **轨迹导出**：长时段传感器读数/区域统计导出 Parquet，供外部分析。

## 8. 图形化呈现系统（对应 R5）

### 8.1 解耦原则
渲染器 = 特殊订阅者。内核维护每tick的**环形缓冲帧**，渲染端滞后 head 约 1~2 帧做插值外推，实现"低tick率高流畅度"。渲染负载永不反压模拟（丢帧优于阻塞）。

### 8.2 分尺度可视化手段
| LOD | 表达方式 |
|---|---|
| L0 刚体 | 实例化网格 + PBR材质 + 接触火花/形变量色图 |
| L1 流体 | FLIP粒子→屏幕空间流体表面 / marching cubes等值面; 气体用体光线步进(密度/温度染色) |
| L1 场 | 切片热力图、等值面、流线/LIC纹理、矢量glyph箭头场 |
| L1 固体 | FEM形变网格 + 应力/应变伪彩色 |
| L2/L3 分子 | 空间填充/球棍模型, GPU实例化百万级; 键合力着色 |
| 通用 | 时间曲线示波器(传感器)、剖切平面、爆炸视图、慢放 |

### 8.3 技术路线
- **Web Viewer（首选交付）**: TypeScript + WebGPU(降级WebGL2) + Three.js生态；FlatBuffers解析；插值渲染循环与模拟tick解耦。
- **原生渲染器（后期可选）**: 复用同一状态流协议，Rust+wgpu，面向VR/大规模场景。
- 相机即注意力：Viewer的视锥自动上报作为LOD注意力输入（§5.2），用户看到哪里哪里精细——体验与算力自然统一。

## 9. 正确性保障体系（平台的公信力所在）

1. **解析解验证库**（CI必过）：抛体(含空气阻力)、谐振子周期、开普勒轨道能量漂移<1e-9、Poiseuille流剖面、Stokes阻力、热传导Fourier解、带电立方Laplace多极解…
2. **守恒监控器**：每tick输出总质量/动量/能量/角动量残差，作为一级健康指标暴露在 `/stats`。
3. **跨层自洽测试**：§4.5 的 D=kT/(6πηR) 涌现验证、理想气体 PV=Nk_BT 从MD盒涌现、重力下流体静压 ∂p/∂z=-ρg。
4. **收敛性测试**：固定问题加密网格/缩小时步，误差阶数须符合所用格式的理论阶。
5. **混沌透明化**：提供两世界的Lyapunov发散度量工具，明示"何时开始偏离"，用于教育用户精度的意义。

## 10. 技术选型

| 组件 | 选型 | 理由 |
|---|---|---|
| 内核语言 | **Rust** | 性能+内存安全+ fearless concurrency; 多世界隔离可靠 |
| 并发/ECS | bevy_ecs（仅取ECS，包一层自有trait） | 成熟的 archetype ECS + 调度器，加速MVP |
| GPU计算 | wgpu compute shader（WGSL） | 跨厂商GPU，一套代码覆盖DX12/Vulkan/Metal |
| IPC/传输 | tonic(gRPC) + tokio-tungstenite(WS) | 数据面高性能 + 浏览器可达 |
| 序列化 | FlatBuffers(热路径零拷贝) / protobuf(控制面) / Parquet(轨迹) | 各取所长 |
| 存储 | redb(嵌入KV存chunk) + 内容寻址去重 | 无外部依赖起步，接口留出S3适配位 |
| Viewer | TypeScript + WebGPU + Three.js | 触达面最大 |
| 测试 | criterion(基准) + 验证库CI | 见§9 |

## 12. 分阶段实施计划

| 阶段 | 周期(1~2人全职) | 交付物 | 验收标准 |
|---|---|---|---|
| **P0 MVP** | 4~6周 | ws-core/domain/engine + L0刚体 + L1b流体(FLIP) + REST/WS最小接口 + Web Viewer基础版 | 抛体/碰撞/水槽三demo通过解析解CI; 60Hz下1万刚体+10万流体粒子单机流畅 |
| **P1 精度体系** | +6~8周 | 八叉树Region + 注意力LOD + 预算控制器 + refine/coarsen握手区 + 快照/重放/分叉 | 同一世界不同预算下自动分配LOD且守恒残差达标; kill后从快照+日志精确复原 |
| **P2 微观层** | +8~10周 | L2粗粒化 + L3全原子MD(GPU) + 材料自标定管线 + 分子可视化 | D=kT/6πηR涌现测试通过; 材料库≥10种由MD标定的材料 |
| **P3 平台化** | 持续 | 多worker分布算力 · 世界迁移 · 配额计费 · Python/TS正式SDK · 原生渲染器 | 双机分布式世界; 第三方项目零内核知识接入完成完整仿真 |

**性能数量级预期**（单台桌面级硬件，诚实估计）：
- L0: 10⁴~10⁵活跃刚体 @60Hz；睡眠体10⁶+
- L1: FLIP流体 3×10⁵~10⁶ 粒子(GPU)；256³网格气相实时
- L3: 消费级GPU约 10⁶~10⁷ atom·step/s → 10⁵原子体系 ≈ 每天微秒级物理时间 → **只用于热点小域**，这正是LOD体系存在的理由

## 13. 风险登记册

| 风险 | 等级 | 缓解 |
|---|---|---|
| 跨尺度耦合不稳定(握手区数值反射) | 高 | P1专项攻关；保守的切换迟滞+守恒对账熔断 |
| GPU跨平台数值不一致破坏确定性 | 中 | GPU只做力累加等容错段；积分与判定留在CPU float64；文档化确定性等级 |
| 范围蔓延(想一次做全LOD) | 高 | 铁律: 每阶段验收标准冻结, 未过CI不开下一阶段 |
| MD层性价比误解(用户期望微观全域) | 中 | 产品层面明确"注意力定价": 微观精度是稀缺资源 |
| bevy_ecs上游破坏性变更 | 低 | trait隔离层包裹, 版本锁死 |
